# bitget-supermarket-trader

> **AI 原生短期交易系统** —— Bitget 美股永续合约(USDT-FUTURES,全仓模式)。
> **AI 是唯一决策者**:程序只负责交易所约束、订单执行、账目审计与安全兜底。

## 设计哲学

传统量化:人写规则 → 程序按规则下单,AI 只在边缘打补丁。
本项目反过来:

```
人是约束的提供者, AI 是唯一的决策者。
```

- **AI 决定一切**:选标的、BUY/HOLD/CLOSE、做多还是做空、杠杆、单笔保证金、最多持有几个仓位、资金利用率,以及每一次止损/止盈价位与调仓。
- **程序只做四件事**:①把交易所的物理约束变成硬门控 ②安全执行订单与保护单 ③账目审计(以交易所成交流水为唯一权威)④宕机/断网/异常时的安全兜底。
- **允许零交易**:HOLD 永远是合法输出。宁可错过,不做没理由的单。

## 当前策略(2026-09 定稿)

### 1. 反转后顺势 —— 唯一入场方式

不做"追趋势中段"(那是"买在最高处"的来源),也不做"猜底接刀"。只做:

```
等一段连续下行/上行走完(价格跌不动 / 涨不动)
        ↓
出现反转确认形态  ← 程序用价格+成交量检测, 作为硬门控
        ↓
确认后第一时间进场(此时价格仍在启动区低位)
```

**反转确认形态**(程序检测,15m 优先、5m 兜底):

| 方向 | 确认条件(任一即可) |
|---|---|
| 底部反转 → 做多 | 长下影阳线 / 收盘收复前 2 根高点 / 放量长阳吞没前根阴线 + 不再创新低 |
| 顶部反转 → 做空 | 长上影阴线 / 收盘跌破前 2 根低点 / 放量长阴吞没前根阳线 + 不再创新高 |

**没有反转信号 → 程序直接拒开**(连"顺势追"也会被拦掉)。唯一的例外是深跌 40%+ 且出现企稳信号的票(低风险尝试通道)。

### 2. 出场:情况不对就跑

```
反转失效(持仓方向出现反向反转信号) → 程序直接离场, 不给 AI 犹豫空间
动量乏力 + 浮盈 ≥ 1.5%              → 程序直接兑现(实证回吐成亏损概率 66.2%)
持有满 48 小时                       → 时间止损, 强制平仓(防滞销)
交易所侧 TPSL(止损/止盈)            → 每一笔持仓必挂, 宕机时唯一保护
```

### 3. 看盘分工:只看价格,不看指标

| 周期 | 角色 | 输入形式 |
|---|---|---|
| 4H | 背景(连续变化不可对着干) | 近 24 根 OHLC + 价格结构(连续上行/下行/震荡) |
| 1H | **操作主周期** | 近 24 根 OHLC + 价格结构 |
| 15m | 入场时机 | **近 48 根(≈12 小时)** OHLC |
| 5m | 最后一档微调 | 近 20 根 OHLC |

- **每根 K 线都给 开/高/低/收 四个价格** —— AI 的判断依据是价格随时间的变化,不是任何指标。
- 指标行(RSI/MA/ADX/乖离)已**全部从 AI 输入中移除**(实证:对短期无预测力;留着反而诱发"凭印象引用指标数值"的幻觉)。
- 已删除:日线位、周线、日线级大盘门控(短期交易不需要长周期结论)。

### 4. 仓位与风险参数

| 参数 | 值 | 由谁决定 |
|---|---|---|
| 杠杆 | 3 ~ 20x | **AI** 按行情波动决定 |
| 单批保证金 | $0.5 ~ $5 | **AI** |
| 总仓位数 | 1 ~ 6 | **AI** |
| 名义上限 | 净值 × 3 ~ 6 | **AI** |
| 止损 SL | 1.5% ~ 5%(>5% 程序拒绝) | AI 给价,程序校验 |
| 止盈 TP | 目标 2~3%(上限 10%,>10% 拒绝) | AI 给价,程序校验 |
| 盈亏比 RR | ≥ 1.0 | 程序校验 |
| 空头仓位 | ≤ 3(与多头完全对称) | 程序约束 |
| 单标的批次 | ≤ 3(加仓需递减) | 程序约束 |
| 熔断 | 日亏 5% 停当日 / 连亏 3 次停 2h | 程序 |

## 给 AI 的输入(数据即事实)

每轮决策,AI 收到的都是**事实**,不含程序的价值判断:

```
大盘实时     SPY / QQQ 现价与 24h 涨跌(只用于天气戒备, 不做方向门控)
标的行情     现价 / 24h / 时段 / 盘口买卖量比 / 资金费率
价格结构     4H·1H·15m 连续上行/下行/震荡(纯高低点位移比例)
反转信号     底部反转迹象 / 顶部反转迹象 / 无(附具体依据)
周期桶       上涨 / 下跌 / 震荡(热门池 25 只按 1H 价格结构分桶)
OHLC 数组    4H 24根 / 1H 24根 / 15m 48根 / 5m 20根(开高低收)
走势形态     近 3 根 K 线形态压缩(阳/阴/长下影/上影/吞没)+ 区间 + 关键位
账户         净值 / 可用 / 已用名义 / 持仓明细与浮盈 / 当日盈亏
历史         该标的的历史交易结果(仅供反思, 行情会反转)
```

程序的硬门控与 AI 决策**同源同数据**,不存在"程序按日线拦、AI 按小时想开"的矛盾。

## 风控与安全(程序级硬门控)

| 机制 | 说明 |
|---|---|
| 反转门控 | 无反转信号 = 拒开(唯一入场方式) |
| 天气门 | SPY 24h 跌 ≥3% 或盘中急跌 ≥2.5% → 当日禁开;查询失败 → 保守禁开(fail-safe) |
| 全仓保证金 | 总名义 ≤ 净值 × 6(爆仓线约 -16%);单仓不单独爆仓 |
| TPSL 强制 | 每笔持仓必须挂交易所侧止损止盈;止盈上限 10%、止损上限 5% |
| 裸仓兜底 | 开仓保护单失败 → 立即补挂 → 破位则贴现实价重挂 → 仍失败则**自动市价平仓**(绝不裸奔) |
| 账目审计 | 每日以交易所成交流水(fills)为唯一权威自动对账,不一致即报警 |
| 实盘三重解锁 | `LIVE_CONFIRM=yes` + 有效密钥 + 账户余额 ≥ $1,缺一不可启动实盘 |
| 密钥隔离 | 全部凭据仅存服务器 `.env`(0600),代码与仓库内零密钥 |

## 架构

```
src/supermarket/
├── engine.py        主循环: 账户→对账→管仓→扫描开仓→复盘; 硬门控与兜底
├── market.py        行情组装: 五档 K线 / 价格结构 / 反转信号 / 周期桶 / 盘口 / 资金费率
├── indicators.py    纯价格计算: 形态压缩 / 反转K线 / 连续变化方向(无指标依赖)
├── ai.py            LLM 网关(OpenAI 兼容)+ 决策解析(开仓/管仓双路)
├── prompts.py       提示词构建(开仓 / 管仓 / 复盘三套)
├── risk.py          风控校验: 仓位/杠杆/保证金/名义/止损止盈/盈亏比/批次
├── execution.py     执行: 下单 + TPSL 挂载与自愈 + 平仓 + 订单流水
├── memory.py        决策账本: 开仓/平仓/持仓记录 + 按标的的历史归因
├── bitget_client.py Bitget 统一账户(v3)接口: 签名 / 行情 / 交易 / 策略单
├── notify.py        Telegram 通知(开仓/平仓/风控事件/日报)
├── telegram_bot.py  远程指令与查询
├── sentiment.py     市场情绪(池内宽度 + VIX), 仅作事实输入
└── config.py        配置加载(yaml + .env 注入)
```

运行节拍:盘中管仓每 5 分钟、开仓扫描每 15 分钟;盘前盘后 15 分钟;隔夜 30 分钟;周末停机(持仓由交易所侧 TPSL 保护)。

## 实证结论(数据说话)

策略迭代全部以历史数据检验,不做"感觉派"调整。部分结论:

**已被数据否决**
- 固定止盈会截断趋势利润(11.6 万样本:TP+6% 均值 +0.21% vs 不止盈 +1.02%)→ 止盈降级为极端保护位
- 量比 / MACD 多空 / 布林位置:各桶胜率 58~60% 无区分度 → 从输入删除
- 日线级大盘门控:滞后于短期节奏,曾把趋势票全部拦死 → 移除(保留实时天气戒备)
- PEAD 效应 / BTC 前瞻性 / VIX 低位:在美股永续上未被验证 → 未采用

**被数据支持**
- 动量"乏力"状态浮盈回吐成亏损概率 66.2%(vs 推进中 40.1%)→ 程序兜底兑现
- 亏损单中位持有 16.6h vs 盈利单 7.4h → 短期化 + 48h 时间止损
- 顺势中的高位不是风险(强趋势追高样本盈利),真正的风险是"势不成立"

> 研究脚本与样本数据见 `research/`,结论文档见 `docs/STRATEGY.md`。

## 快速开始

```bash
# 1) 安装
python3.11 -m venv .venv && .venv/bin/pip install -e .

# 2) 配置
cp .env.example .env && chmod 600 .env      # 填入 Bitget 与 LLM 密钥
# config.yaml 默认 mode: paper(模拟), 先跑纸面验证

# 3) 跑测试
.venv/bin/python -m pytest tests/ -q        # 150 passed

# 4) 纸面运行(不碰真实资金)
.venv/bin/python -m supermarket.engine --mode paper

# 5) 实盘(三重解锁后)
LIVE_CONFIRM=yes .venv/bin/python -m supermarket.engine --mode live
```

systemd 服务模板见 `deploy/`;实盘前建议先跑 `scripts/prelive_check.py`。
