# PLAN — bitget-supermarket-trader(超市策略美股永续交易系统)

## 1. 目标

在 Bitget 美股永续合约(USDT-FUTURES, symbolType=perpetual, 标的为美国股票)上,
运行一个 **AI 全权决策** 的多头交易系统,遵循用户的"超市"理念:

- 每笔下单保证金 ≤ $2,杠杆 20 倍 → 单笔名义 ≈ $40
- **全仓(crossed)保证金模式**:单仓不会被单独强平,账户整体净值承担所有持仓亏损
  ——这是"拿住亏损单等回涨"能够成立的数学前提
- 只做多(BUY),挑选 处于上涨周期 / 可能上涨 的美股
- 止盈风格:赚 1~3% 快速兑现(超市进货→加价卖出)
- 亏损风格:趋势未坏 → 拿住等回涨(全仓扛得住);趋势明显破坏/利空 → AI 认错止损
- 账户小资金试水($20~50),少量单子,整体很难爆仓

## 2. 核心风险数学模型(设计依据,已与用户确认)

全仓爆仓线:账户净值损失 ≈ 净值 − 维持保证金总额(≈总名义 × 0.5%)
才触发全仓强平。以 $20 账户、每仓 $40 名义计:

| 持仓数 | 总名义 | 爆仓线(合计亏损) | 等价场景 |
|---|---|---|---|
| 1 | $40 | ≈$19.5(−97% 账户) | 单票跌 49% |
| 2 | $80 | ≈$19.4(−97%) | 两票各跌 24% |
| 5 | $200 | ≈$19(−95%) | 整体跌 9.5% |
| 10 | $400 | ≈$18(−90%) | 整体跌 4.5% |

**设计约束(代码强制):**
- `MAX_NOTIONAL_MULT = 6` → 总名义 ≤ 账户净值 × 6
- `MAX_POSITIONS = 净值 / 10`(向上取整,至少 1)→ 保证金占用 ≤ 净值 60%
- $20 账户 → 最多 2 仓;$30 → 3 仓;$50 → 5 仓
- 每仓必然挂交易所侧 TPSL(止损/止盈),AI 未给止损 → 拒绝开仓
- 单日亏损 > 30% 净值 → 停止新开仓(次日恢复)
- 连续 3 次止损(实盘按真实成交计)→ 暂停 2 小时冷静
- 资金费率 8h 结算:AI prompt 注入当前费率与持仓成本(多头正费率=付钱)

## 3. 范围

**做(本项目交付):**
- 完整工程:行情采集、指标、"超市策略"AI prompt(开仓+管仓)、风控、
  paper 模拟执行、真实执行(Bitget v2)、记忆与复盘循环、CLI、测试
- Paper 模式端到端验证(真实行情+真实费率+真实资金费率,虚拟账户)
- 实盘模式:默认关闭,需要 (a) 用户确认 (b) 有效 Bitget 新密钥 (c) 账户已充值

**不做:**
- 不做任何程序化策略/规则评分预筛(指标只作 AI 的事实输入)——用户铁律
- 不做空(用户本轮明确只做多)
- 不做跟单/网格/马丁格尔等自动加仓——AI 每笔独立决策
- 不做 Web 仪表盘(后续再说,CLI 状态输出足够本轮验证)

## 4. 里程碑

- M1: 三文档完成(本文档)
- M2: 骨架+config+密钥模板(uv 环境)
- M3: Bitget 客户端打通(公开行情/账户/下单/TPSL,read-only 验证)
- M4: 指标/风控/决策/执行/记忆模块 + 单元测试
- M5: Paper 模拟端到端验证,输出交易日报告
- M6: 部署(systemd)+ 交接清单(新密钥、充值、实盘开启步骤)

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| LLM 不可用/超时 | Provider 层自动 HOLD(不开仓=最安全),熔断 + 重试 |
| AI 给出危险仓位(SL 太远/TP 太近) | 风控模块硬校验:RR≥设定、SL 距离上限、名义/仓数上限,违规拒单 |
| 交易所 TPSL 未挂上 | 下单流程先挂 TPSL 再建本地持仓;启动对账补挂 |
| 全仓系统性风险(整体大跌) | 名义敞口 ≤ 净值×6 硬约束 + 日亏 30% 熔断 |
| 密钥泄露 | 密钥只存 .env(0600),聊天/日志永不明文;暴露即作废 |
| 标的杠杆不足 20 倍(如 AAOI maxLever=20、MUSDT=10) | 合约规格表驱动,实际可用杠杆取 min(20, maxLever) |

## 6. 用户验收标准

1. Paper 模式在真实行情下连续运行,能看到 AI 决策 → 开仓 → 止盈/止损 → PnL 复盘 全链路
2. 风控硬约束可被单元测试证明(名义上限/熔断/缺SL拒单)
3. 实盘开关显式(默认关),开启需要用户当面确认 + 有效密钥 + 已充值
