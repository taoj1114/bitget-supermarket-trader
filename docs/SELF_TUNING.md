# AI 自迭代系统(Self-Tuning & Code Evolution)

> 目标:让系统**自己看懂自己的成交记录、自己发现并修复程序问题** —— 人类只提供护栏。

系统有两级自我迭代,分工明确:

| 级别 | 模块 | 能改什么 | 节拍 |
|---|---|---|---|
| 策略自调 | `self_tune.py` | 提示词「自学习经验区」+ 白名单参数 | 每日 08:40 |
| **代码自迭代** | `code_evolve.py` | **程序源码本身**:修 bug、消除不合理设计、补小功能 | 每日 09:00 |

---

## 一、策略自调(self_tune)

```
决策留痕(带特征)  →  每日复盘统计  →  AI 提案  →  程序护栏校验  →  应用(规则区/参数)
      ↑                                                                      ↓
      └────────────  观察 ≥10 笔  ←  通知  ←  版本快照(可回滚)  ←───────────┘
```

1. **决策留痕**:每次开仓把决策时的特征(`反转类型 / 周期桶 / 1H结构 / 动量 / 杠杆 / 保证金`)写进账本,
   与最终盈亏绑定 —— 这是自我审视的**证据基础**。
2. **每日复盘**:汇总全部已平仓交易,按 7 个维度分组(反转类型/周期桶/方向/时段/1H结构/动量/持有时间),
   附最近 15 笔明细(理由 + 特征 + 盈亏)与"已证伪"清单。
3. **AI 提案**:输出结构化 JSON —— 分析 + ≤3 条变更,每条必须引用**具体统计数字**。
4. **程序护栏**:只允许经验条目(≤20 条,≤200 字)+ 白名单参数(范围钳制);
   **用户偏好锁定**(止盈 2~3%、止损 1.5~5%、盈亏比下限、入场方式=反转后顺势、空单对称)——提了也被拒。
5. **应用与回滚**:变更前存快照 → 观察 ≥10 笔 → 平均盈亏变差 → **自动回滚** + 记入"已证伪"。

## 二、代码自迭代(code_evolve)

让程序像维护者一样工作:读日志与代码 → 定位问题 → 给出精确补丁 → 自测 → 上线 → 看效果。

```
健康检查(上一轮改动是否出事 → 出事则回滚)
   → 信号收集(24h ERROR/Traceback · 服务状态 · 测试结果 · 交易统计 · 项目结构)
   → AI 提案(可多轮「探查代码」: 申请查看具体文件行段 → 再给补丁)
   → 硬护栏校验 → 应用 → 语法检查 + 全量测试 → 通过才提交 → 打 tag → 重启服务 → 通知
```

### 硬护栏(不通过即拒,程序强制)

| 护栏 | 说明 |
|---|---|
| **保护清单** | `bitget_client.py`(签名/接口)、`risk.py`(风控底线)、`execution.py`(TPSL/裸仓兜底/平仓)、`config.py`(底线参数)、自迭代自身 —— **永不自动改** |
| **既有测试不可改** | 只允许新增 `tests/test_evolve_*.py` —— 防止"改测试让自己通过" |
| **路径白名单** | `src/supermarket/`、`scripts/`、`docs/`、`README.md`、新增 evolve 测试 |
| **唯一性** | 每处改动必须能精确匹配(片段在文件中唯一出现),防误替换 |
| **测试闸门** | 语法 + 全量 pytest 必须全绿,否则**立即还原**,不留痕迹 |
| **回滚点** | 每轮上线前打 tag `evolve-<时间>`;下一轮健康检查发现异常(服务掉线/ERROR 激增)→ 自动 revert |
| **通知** | 每轮改动/被拒/回滚都推送 Telegram,含改动文件与理由 |

### AI 的探查协议

AI 若不看清代码就能给补丁,那是猜。所以协议支持多轮:

```json
{"findings": [{"kind": "bug", "severity": "high", "what": "...", "evidence": "..."}],
 "need_files": ["src/supermarket/engine.py:1180-1240"],
 "edits": []}
```
系统把申请的代码片段(带行号)发回,AI 下一轮再给 `edits`(最多 3 轮探查)。

## 三、实测记录

**策略自调第一次(2026-09-29,35 笔真实成交)**:
```
AI 分析: 亏损集中在 regular(16笔 胜率37.5% -1.09)与 pre_market(9笔 44.4% -1.01)
         两时段 25 笔 ≈ 全部亏损 -2.24; 6-24h 持仓平均为负 = 浮盈被拖回
应用: ①两时段开新仓需放量突破确认 ②浮盈单 1-6 小时内兑现
拒绝: AI 提议 min_rr 1.0→1.5(与其用户偏好冲突) → 程序作废 + 记入已证伪
```

**代码自迭代第一次(findings 摘要)**:
```
① bug:   35 笔成交的"反转类型"全为未知 → 留痕字段在历史记录中缺失(已改为区分"旧记录(未留痕)")
② 隐患:  deepseek-v4.1-flash 单轮决策 57.8s, 而 LLM 超时阈值 45s → 必然超时降级 HOLD
         (已修复: config.llm.timeout_s 45 → 120)
③ 观察:  <1h 持有 7 笔平均 -0.25 明显偏差(反转失效兜底是否过早, 继续观察)
```
—— 第一次运行就抓出一个必然导致决策降级的超时配置错误。

## 四、运维

```bash
# 策略自调
.venv/bin/python -m supermarket.self_tune --dry-run     # 只看提案
cat state/live/learned_rules.md                          # 当前经验
cat state/live/tuning_log.json                           # 版本与回滚记录

# 代码自迭代
.venv/bin/python -m supermarket.code_evolve --dry-run    # 只看 findings/补丁
cat state/live/code_evolve_log.json                      # 每轮改动与回滚记录
git tag --list 'evolve-*'                                # 可用回滚点

# 定时器
systemctl list-timers 'supermarket-*'
systemctl status supermarket-selftune.timer supermarket-evolve.timer
```

find 唯一性、语法失败自动还原、自迭代自我保护。
